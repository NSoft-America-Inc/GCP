# GitHub Issue Creator

프로젝트 컨벤션에 따라 이슈를 분류하고 등록하며, 명확한 완료 기준을 제시한다.

---

## 1. 이슈 분류 및 네이밍 규칙

| 유형 | 네이밍 규칙 | 기본 라벨 |
|---|---|---|
| **기능 (Feature)** | `[feat] {내용}` | `enhancement` |
| **서브 이슈 (Sub)** | `[Sub #{부모}] {내용}` | `{타입}` |
| **버그 리포트 (Bug)** | `[Bug] {현상}` | `bug` |

- **타입**: `feat`, `fix`, `refactor`, `chore`, `docs`
- **라벨 확인**: `gh label list`로 사전 확인 후 사용한다.

---

## 2. 이슈 본문 템플릿

```markdown
## 개요
{목적 및 작업이 필요한 배경을 2~3줄로 설명}

## 작업 내용
- [ ] {작업 단위 1: 구체적 파일/함수 명시}
- [ ] {작업 단위 2: 처리 방식 명시}

## 완료 기준
- [ ] {검증 포인트 1}
- [ ] {검증 포인트 2}
- [ ] 정적 분석 이슈 없음

## 영향 범위
- **산출물**: {파일 경로}
- **영향 범위**: {수정으로 영향받는 타 컴포넌트}
```

---

## 3. 실행 프로세스

1. **컨텍스트 추출**: 사용자 요청 또는 `tasks/orders/{agent}/order-{target}-latest.md`에서 작업 내용을 추출한다.
2. **초안 작성 및 승인**: 이슈 제목과 본문 초안을 먼저 출력하고 "위 내용으로 GitHub 이슈를 생성할까요?" 라고 묻는다.
3. **이슈 생성**: 승인 후 `gh issue create`를 실행한다.
4. **결과 보고**: 생성된 이슈 URL과 번호를 제공하고, 현재 지시서에 이슈 번호를 반영한다.

---

## 준수 사항

- 모호한 제목 지양: "Bug fix" ❌ → "Bug: 로그인 화면 overflow on mobile" ✅
- 선행 작업이 있는 경우 개요 섹션에 명시한다.
- 승인 없이 이슈를 생성하지 않는다.
